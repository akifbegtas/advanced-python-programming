1.1 What is API? & What is FastAPI?

PDF 1 • Slides 1–5 & 61

Bir API (Application Programming Interface), farklı yazılım uygulamalarının birbiriyle iletişim kurmasını sağlayan kurallar ve protokoller bütünüdür. Uygulamaların birbirinden servis talep etmek (Request) ve veri alışverişi yapmak (Response) için kullanabileceği metotları (HTTP Methods) ve veri formatlarını (JSON / XML / HTML) tanımlar.

Definition & Key Features of FastAPI (Slide 4)

FastAPI, standart Python type hints (tip ipuçları) temel alınarak Python 3.10+ ile API'ler geliştirmek için tasarlanmış modern ve yüksek performanslı (high-performance) bir web framework'tür.

  • Fast to code: Geliştirme hızını ciddi ölçüde artırır, daha az kodla daha çok iş yapılır.
  • High performance: Starlette ve Pydantic sayesinde NodeJS ve Go ile yarışacak düzeyde yüksek hız sunar.
  • Easy to use: Öğrenmesi ve kullanması son derece kolaydır.
  • Based on OpenAPI and JSON Schema: Açık standartlar olan OpenAPI ve JSON Schema ile tam uyumludur.

Why Use FastAPI? — Core Advantages (Slide 5)

  • Auto-generated API docs (Swagger UI and ReDoc): Kodunuzdan otomatik olarak etkileşimli dokümantasyon üretir.
  • Built-in validation and serialization with Python type hints: Veri doğrulama ve dönüştürme işlemlerini yerleşik olarak yapar.
  • Asynchronous support (async/await): Eşzamansız programlamayı doğrudan destekler.
  • Dependency injection system: Güçlü ve kullanımı kolay bağımlılık enjeksiyonu mimarisine sahiptir.

1.5 Step-by-Step CRUD API: All 5 Endpoints & Interactive Lab

PDF 1 • Slides 20–25

Slayt 20–25 arasında tam bir bellek içi (in-memory) CRUD uygulaması 5 adımda inşa edilmektedir:

1. Setup & 2. Data Shape and Storage (Slides 20–21)

  • FastAPI: Web sunucusunu inşa eden ana çatı (framework).
  • HTTPException: "404 Not found" gibi HTTP hata yanıtları göndermeyi sağlar.
  • BaseModel: Verimizin şeklini (data shape / template) tanımlar. Item sınıfındaki item: str alanı sayesinde Pydantic veriyi otomatik kontrol eder (metin yerine sayı gelirse hata verir).
  • items: List[Item] = [Item(item="ali")]: Başlangıçta içinde tek bir "ali" öğesi bulunan standart Python listesi.

3. Read All, Create, 4. Read One, 5. Update & Delete (Slides 22–24)

  • GET /: Tüm items listesini döndürür. @app.get(...) bir decorator'dür; URL ve HTTP metodunu altındaki fonksiyona bağlar. response_model yanıtın veri şeklini belirler.
  • POST /items: İstek gövdesinden (request body) yeni bir Item alır, append ile listeye ekler ve güncel listeyi döndürür.
  • GET /items/{item_id}: URL'deki {item_id} dinamik değişkendir (list index). item_id: int metin olan "0" değerini 0 tam sayısına çevirir. İndeks sınır dışındaysa 404 Not Found fırlatır.
  • PUT /items/{item_id}: Belirtilen indeksteki öğeyi yenisiyle değiştirir (items[item_id] = item).
  • DELETE /items/{item_id}: Öğeyi items.pop(item_id) ile listeden siler ve silinen öğeyi döndürür.

⚠️ Important Index Shift Warning on DELETE (Slide 24)

"The ID is just the list position (index). Index 0 is the first item. After a delete, items after it move up one position, so their IDs change." — Burada ID doğrudan Python listesindeki indeks (index) olduğu için, pop(item_id) ile bir eleman silindiğinde ondan sonra gelen tüm elemanlar bir üst indekse kayar ve ID'leri değişir!

Complete 5-Endpoint CRUD Code (Slides 20–24, Lines 1–39) 
# 1. Setup: the tools we use (Slide 20)
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
from typing import List

app = FastAPI()

# 2. The data shape and storage (Slide 21)
class Item(BaseModel):
    item: str

items: List[Item] = [Item(item="ali")]

# 3. Read all and Create (Slide 22)
@app.get("/", response_model=List[Item])
def root():
    return items

@app.post("/items", response_model=List[Item])
def create_item(item: Item):
    items.append(item)
    return items

# 4. Read one item (Slide 23)
@app.get("/items/{item_id}", response_model=Item)
def get_item(item_id: int):
    if item_id < 0 or item_id >= len(items):
        raise HTTPException(status_code=404, detail="Item not found")
    return items[item_id]

# 5. Update and Delete (Slide 24)
@app.put("/items/{item_id}", response_model=Item)
def update_item(item_id: int, item: Item):
    if item_id < 0 or item_id >= len(items):
        raise HTTPException(status_code=404, detail="Item not found")
    items[item_id] = item
    return item

@app.delete("/items/{item_id}", response_model=Item)
def delete_item(item_id: int):
    if item_id < 0 or item_id >= len(items):
        raise HTTPException(status_code=404, detail="Item not found")
    return items.pop(item_id)

Summary: All 5 Endpoints Table (Slide 25)

Method URL CRUD Operation What it does (English / Türkçe Açıklama)
GET / Read List all items — Listedeki tüm öğeleri döndürür.
POST /items Create Add a new item — Listeye yeni bir öğe ekler ve güncel listeyi döndürür.
GET /items/{id} Read Get one item — Belirtilen indeksteki tek bir öğeyi getirir (yoksa 404).
PUT /items/{id} Update Replace one item — Belirtilen indeksteki öğeyi yenisiyle değiştirir.
DELETE /items/{id} Delete Remove one item — Belirtilen indeksteki öğeyi pop() ile siler, sonraki indeksler kayar.

Entity-Relationship (ER) Diagram: Student & Course (Slide 26)

İlişkisel veritabanı tasarımında Primary Key (PK) benzersiz kimliği, Foreign Key (FK) ise başka bir tabloya olan referansı temsil eder:

cURL Command-Line Tool (Slide 28)

curl, bir cihaz ile sunucu arasında komut satırından veri alışverişi (data exchange) yapılmasını sağlayan araçtır. Üç temel bileşeni yönetir:

  • ✅ Headers (-H): Örneğin "Content-Type: application/json".

Student In-Memory CRUD Routes (Slides 27 & 29) 
# List to store data in memory (Slide 29)
students = [
    Student(id=1, name="Ahmed ali", grade=5),
    Student(id=2, name="Mohammed ahmed", grade=3),
]

@app.get("/")
def fun():
    return students

@app.get("/students/")
def read_students():
    return students

# Direct index access without bounds check causes Internal Server Error on /students/2!
@app.get("/students/{student_id}")
def get_student(student_id: int) -> str:
    student_id = students[student_id]
    return student_id

@app.post("/students/")
def create_student(New_Student: Student):
    students.append(New_Student)
    return New_Student

@app.put("/students/{student_id}")
def update_student(student_id: int, updated_student: Student):
    for index, student in enumerate(students):
        if student.id == student_id:
            students[index] = updated_student
            return updated_student
    return {"error": "Student not found"}

@app.delete("/students/{student_id}")
def delete_student(student_id: int):
    for index, student in enumerate(students):
        if student.id == student_id:
            del students[index]
            return {"message": "Student deleted"}
    return {"error": "Student not found"}

1.7 HTTP Response Status Codes, HTTPException & Pydantic Validation

PDF 1 • Slides 32–36

HTTP response status codes, belirli bir HTTP isteğinin başarıyla tamamlanıp tamamlanmadığını belirtir ve 5 ana sınıfta gruplanır (Slide 32):

1xx – 3xx Status Classes

  • 1. Informational responses (100 – 199): İstek alındı, işlem devam ediyor.
  • 2. Successful responses (200 – 299): İstek başarıyla tamamlandı (200 OK, 201 Created).
  • 3. Redirection messages (300 – 399): İsteği tamamlamak için ek yönlendirme gerekiyor.

4xx – 5xx Error Classes

  • 4. Client error responses (400 – 499): İstemci kaynaklı hatalar (400 Bad Request, 404 Not Found, 422 Unprocessable Entity).
  • 5. Server error responses (500 – 599): Sunucu kaynaklı beklenmeyen hatalar (500 Internal Server Error).

1.8 Representational State Transfer (REST), 6-Step HTTP Flow & Parameters

PDF 1 • Slides 37–43

Representational State Transfer (REST) mimarisinde istemciler (Clients), sunucu üzerindeki kaynaklar üzerinde 4 temel CRUD operasyonunu HTTP metotları aracılığıyla gerçekleştirir (Slides 37–39):

REST API ↔ CRUD ↔ HTTP Methods Mapping (Slides 37–39)

  • Create ➔ POST: Send data (Sunucuya yeni veri gönderir/oluşturur).
  • Read ➔ GET: Fetch data (Sunucudan veri okur/getirir).
  • Update ➔ PUT / PATCH: Update data (Mevcut veriyi günceller).
  • Delete ➔ DELETE: Remove data (Mevcut veriyi siler).

6-Step Flow of Communication (Slides 40–41)

  1. Client App (Web tarayıcı veya mobil uygulama) HTTP üzerinden bir Request başlatır.
  2. HTTP protokolü bu isteği Server'a iletir (Forward Request).
  3. Server gelen isteği işlenmesi için FastAPI App'e aktarır (Process Request).
  4. FastAPI App isteği işler ve ürettiği Response'u Server'a geri döndürür.
  5. Server yanıtı HTTP üzerinden geri gönderir (Send Response).
  6. HTTP yanıtı Client App'e teslim eder.
Path Parameters — Dynamic URL Segments (Slides 37 & 42) 
# Path parameters capture dynamic segments of a URL (Slide 42)
@app.get("/users/{user_id}")
async def read_user(user_id: int):
    return {"user_id": user_id}

# Slide 37 Basic Example:
@app.get("/items/{item_id}")
async def read_item(item_id: int):
    return {"item_id": item_id}
Query Parameters — Filtering & Pagination (Slide 43) 
# Optional query parameters allow filtering or pagination (Slide 43)
# Example URL: /items/?skip=0&limit=10
@app.get("/items/")
async def read_item(skip: int = 0, limit: int = 10):
    return {"skip": skip, "limit": limit}

1.10 Dependency Injection, Background Tasks, Middleware & CORS

PDF 1 • Slides 50–54

Dependency Injection & Background Tasks (Slides 51–52)

  • Dependency Injection (Depends): Ortak parametreleri, veritabanı bağlantılarını veya kimlik doğrulama kontrollerini tekrar kullanılabilir fonksiyonlar haline getirerek kod tekrarını (code duplication) önler.
  • Background Tasks (BackgroundTasks): E-posta bildirimi göndermek veya log dosyasına yazmak gibi request-response cycle sırasında kullanıcının beklemesine gerek olmayan işlemleri arka planda çalıştırır.

2.2 Example 5: Check Prime Number (/prime/{num})

PDF 2 • Slide 7

Bir n sayısının asal (prime) olup olmadığını belirleyen parçalı matematiksel fonksiyon (piecewise function) f(n) → {True, False} ve 4 temel algoritma bileşeni (Slide 7):

Piecewise Mathematical Definition (Slide 7):
• False, if n < 2
• False, if ∃i ∈ ℤ such that 2 ≤ i ≤ ⌊√n⌋ and n ≡ 0 (mod i)
• True, otherwise

Explanation of 4 Algorithm Components (Slide 7)

  • 1. Input Validation & Domain (n < 1): Endpoint ilk olarak num < 1 kontrolü yapar. Eğer doğruysa erken sonlanır ve HTTP 400 Bad Request ("Input must be greater than 0.") fırlatır. Böylece çalışma kümesini pozitif tam sayılarla (n ≥ 1) sınırlar.
  • 2. Base Case (n < 2): is_prime fonksiyonu içinde 2'den küçük her sayı (1 dahil) otomatik olarak False döner; çünkü 1 ne asal (prime) ne de bileşik (composite) sayıdır.
  • 3. Square Root Optimization (⌊√n⌋): Bölen arama uzayını n - 1 yerine 2'den int(n**0.5) + 1 değerine kadar sınırlar. Matematiksel olarak bileşik bir sayının kareköküne eşit veya daha küçük en az bir çarpanı olmak zorundadır ($O(\sqrt{n})$ karmaşıklık).
  • 4. Divisibility Test (n mod i == 0): Sayı aralıktaki herhangi bir i değerine tam bölünürse (n % i == 0) bileşiktir (False). Hiçbir bölen bulunamazsa asaldır (True).
CheckPrime.py — Full Implementation (Slide 7) 
from fastapi import FastAPI, HTTPException

app = FastAPI()

def is_prime(n: int) -> bool:
    if n < 2:
        return False
    for i in range(2, int(n**0.5) + 1):
        if n % i == 0:
            return False
    return True

@app.get("/prime/{num}")
async def prime(num: int):
    if num < 1:
        raise HTTPException(
            status_code=400,
            detail="Input must be greater than 0."
        )
    return {"is_prime": is_prime(num)}

# Euclidean algorithm to calculate GCD
def euclidean_algorithm(u: int, v: int) -> int:

4.1 Defining WebSockets, Full-Duplex Protocol & Multi-Client Broadcasting

PDF 4 • Slides 1–6

HTTP vs. WebSocket (Slide 2): Standart HTTP protokolü Request-Response prensibine dayanır; sunucudan veri almak için her zaman istemcinin (Client) önce istek başlatması gerekir. Bir sohbet (chat) uygulamasında yeni mesaj gelip gelmediğini kontrol etmek için saniyede bir HTTP isteği atmak (polling) devasa bir kaynak israfıdır. Bu yüzden WebSocket protokolü geliştirilmiştir: İstemci ile sunucu arasında gerçek zamanlı (real-time) ve çift yönlü (two-way / full-duplex) kalıcı bir iletişim tüneli (persistent connection) açar.

Handling Multiple Connections & Message Broker (Slide 3)

  • Single Server Broadcast (Figure 8.4): Birden fazla istemci (Client 1, Client 2, Client 3) sunucuya açık bir WebSocket tüneliyle bağlıdır. Bir istemci mesaj gönderdiğinde (Sends message), sunucu bu mesajı bağlı tüm diğer istemcilere yayınlar (Broadcasts message).
  • Multiple Server Workers with a Message Broker (Figure 8.6): Üretim ortamında birden fazla sunucu işçisi (Worker 1, Worker 2) olduğunda, farklı worker'lara bağlı istemcilerin birbirinin mesajını alabilmesi için ortada bir Message Broker (ör. Redis Pub/Sub) kullanılır.

WebSocket Protocol & FastAPI Integration (Slides 5–6)

  • Protocol for full-duplex communication: İstemci ve sunucu aynı anda birbirine veri gönderebilir.
  • Maintains persistent connection: Tek bir el sıkışma (handshake) sonrası bağlantı açık kalır.
  • FastAPI Integration: Yerleşik async desteği, kolay @app.websocket uç noktaları ve çoklu bağlantı yönetimi sunar. Chat uygulamaları, canlı bildirimler (live updates) ve gerçek zamanlı paneller için idealdir.

4.2 Core WebSocket Functions, Connection Management & Event Handling

PDF 4 • Slides 7–11

Core WebSocket & Message Functions (Slides 7 & 9)

  • await websocket.accept(): Gelen WebSocket bağlantı isteğini kabul eder.
  • await websocket.receive_text(): İstemciden ham metin (raw text) mesajı alır.
  • await websocket.send_text(): İstemciye metin yanıtı gönderir.
  • await websocket.receive_json(): Gelen JSON mesajını alır ve otomatik ayrıştırır (parse).
  • await websocket.send_json(): JSON formatında mesaj gönderir.

4.3 ConnectionManager Class Implementation, Sequence & Class Diagrams

PDF 4 • Slides 12–15
WebSocket.py — class ConnectionManager (Slides 12 & 14) 
from fastapi import FastAPI, WebSocket, WebSocketDisconnect
from typing import List
import json
from datetime import datetime

app = FastAPI()

class ConnectionManager:
    def __init__(self):
        self.active_connections: List[WebSocket] = []
        self.connection_count = 0

    async def connect(self, websocket: WebSocket):
        await websocket.accept()
        self.active_connections.append(websocket)
        self.connection_count += 1
        print(f"New connection established. Total connections: {self.connection_count}")

    def disconnect(self, websocket: WebSocket):
        self.active_connections.remove(websocket)
        self.connection_count -= 1
        print(f"Connection closed. Total connections: {self.connection_count}")

    async def broadcast(self, message: str):
        print(f"Broadcasting message: {message}")
        for connection in self.active_connections:
            await connection.send_text(message)

manager = ConnectionManager()

Sequence Diagram — 3 Phases (Slide 13)

  • 1. Connection Establishment: Chat Client (chat.html) ➔ WebSocket Connection Request ➔ WebSocket Server ➔ Connect(websocket) ➔ Add to active_connections ➔ Connection Accepted.
  • 2. Normal Message Flow: İstemci mesaj gönderir ➔ Sunucu Parse JSON Message ve Add timestamp & client_id işlemlerini yapar ➔ Connection Manager üzerinden tüm bağlı istemcilere Broadcast Message gönderir.
  • 3. Disconnect Handling: Bağlantı kapanır (Connection Closed) ➔ Disconnect(websocket) ile active_connections listesinden çıkarılır ➔ Diğer istemcilere ayrılma mesajı yayınlanır (Notify other clients).

4.4 WebSocket Endpoint Implementation & Client Interface HTML

@app.websocket("/ws/{client_id}") Implementation (Slide 16) 
@app.websocket("/ws/{client_id}")
async def websocket_endpoint(websocket: WebSocket, client_id: str):
    await manager.connect(websocket)
    print(f"Client {client_id} connected")
    try:
        while True:
            data = await websocket.receive_text()
            try:
                message_data = json.loads(data)
                timestamp = datetime.now().strftime("%H:%M:%S")
                message_data.update({
                    "client_id": client_id,
                    "timestamp": timestamp
                })
                print(f"Received from client {client_id}: {message_data['message']}")
                await manager.broadcast(json.dumps(message_data))
            except json.JSONDecodeError:
                print(f"Received plain text from client {client_id}: {data}")
                await manager.broadcast(f"Client {client_id}: {data}")
    except WebSocketDisconnect:
        manager.disconnect(websocket)
        disconnect_message = f"Client #{client_id} left the chat"
        print(disconnect_message)
        await manager.broadcast(json.dumps({
            "client_id": "system",
            "message": disconnect_message,
            "timestamp": datetime.now().strftime("%H:%M:%S"),
            "type": "disconnect"
        }))

Endpoint Setup & Key Features (Slide 16)

  • Route definition with client_id: Her istemci benzersiz bir ID ile /ws/{client_id} adresine bağlanır.
  • Continuous message loop (while True): Bağlantı açık olduğu sürece await websocket.receive_text() ile mesajları dinler.
  • JSON message parsing & Fallback: Mesaj geçerli bir JSON ise içine client_id ve timestamp ekler; değilse json.JSONDecodeError yakalayarak düz metin olarak yayınlar.
  • Disconnect handling (WebSocketDisconnect): İstemci sekmeyi kapattığında bağlantıyı listeden siler ve "type": "disconnect" sistem mesajını yayınlar.

// Slides 27 & 29: Initialize WebSocket with random clientId
const clientId = Math.random().toString(36).substring(7);
const ws = new WebSocket(`ws://localhost:8000/ws/${clientId}`);
const messages = document.getElementById('messages');
const connectionStatus = document.getElementById('connectionStatus');

function updateConnectionStatus(connected) {
    connectionStatus.textContent = connected ? 'Connected' : 'Disconnected';
    connectionStatus.className = connected ? 'connected' : 'disconnected';
}

ws.onopen = function() { updateConnectionStatus(true); };

ws.onmessage = function(event) {
    try {
        const data = JSON.parse(event.data);
        const messageDiv = document.createElement('div');
        if (data.type === 'disconnect') {
            messageDiv.className = 'message system';
            messageDiv.textContent = data.message;
        } else {
            messageDiv.className = `message ${data.client_id === clientId ? 'user' : 'other'}`;
            messageDiv.innerHTML = `
                ${data.client_id === clientId ? 'You' : 'Client ' + data.client_id}:
                ${data.message}
                <span class="timestamp">${data.timestamp}</span>`;
        }
        messages.appendChild(messageDiv);
        messages.scrollTop = messages.scrollHeight; // Auto-scroll
    } catch (e) {
        const messageDiv = document.createElement('div');
        messageDiv.className = 'message system';
        messageDiv.textContent = event.data;
        messages.appendChild(messageDiv);
    }
};

// Slide 28: Send JSON formatted message & Enter key listener
function sendMessage() {
    const messageInput = document.getElementById('messageText');
    const message = messageInput.value.trim();
    if (message) {
        ws.send(JSON.stringify({ message: message }));
        messageInput.value = '';
    }
}

document.getElementById('messageText').addEventListener('keypress', function(e) {
    if (e.key === 'Enter') { sendMessage(); }
});

// Slide 30: Error Handling on Client
ws.onerror = function() {
    updateConnectionStatus(false);
    const messageDiv = document.createElement('div');
    messageDiv.className = 'message system';
    messageDiv.textContent = 'Error occurred';
    messages.appendChild(messageDiv);
};
